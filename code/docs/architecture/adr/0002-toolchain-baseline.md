# ADR-0002: Toolchain baseline and version pins

- **Status:** Accepted
- **Date:** 2026-09-17; rewritten on 2026-11-06 for the ASP.NET Core API (ADR-0006, section 8). Git keeps the NestJS version.

## Context

The web app was scaffolded with `create-next-app` 16.3.5. The API began in NestJS and was ported to ASP.NET Core, which has served production since 2026-11-06 ([ADR-0006](0006-aspnet-core-api.md)). Several "latest" tags point at versions that are not safe defaults, so this ADR records what was chosen and why, and upgrades are deliberate.

Guiding rule: **use the latest stable release, not the latest available release.**

## Decision

### The web app and the repository

| Area                 | Choice                                                                                                                                              | Reason                                                                                                                                                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Runtime              | Node.js 24 LTS, at least 24.20.0 (`.nvmrc`, `engines: >=24.20.0 <25`)                                                                               | Node 26 is still "Current", not LTS. The floor of 24.20.0 is explained below the tables.                                                                                                                                             |
| Package manager      | pnpm 11 workspace (`apps/*`)                                                                                                                        | Planned baseline. pnpm 12 exists; upgrading is a separate decision.                                                                                                                                                                  |
| Supply-chain gate    | Respect pnpm's `minimumReleaseAge` (about one day)                                                                                                  | Prefer version ranges that resolve to releases older than the gate instead of adding `minimumReleaseAgeExclude` entries.                                                                                                             |
| Security overrides   | `overrides` in `pnpm-workspace.yaml` force patched versions of transitive dependencies whose parents lag, each within the major the parent asks for | Security review (2026-10-08). Drop an entry once its parent has caught up, or once nothing pulls it in; `pnpm audit` and `pnpm why` show which ([security review](../../testing/security-review.md)).                                |
| Install scripts      | Every dependency build script is listed in `pnpm-workspace.yaml` `allowBuilds`, allowed or denied                                                   | pnpm blocks unlisted scripts, and in CI (`CI=true`) `pnpm install` fails with `ERR_PNPM_IGNORED_BUILDS`. Decide allow or deny when adding a dependency that has install scripts.                                                     |
| TypeScript           | `~6.0.3`                                                                                                                                            | TypeScript 7 (native) is `latest` on npm, but typescript-eslint supports `<6.1.0`. The tilde range blocks 6.1 until typescript-eslint supports it.                                                                                   |
| Web framework        | Next.js 16.4, React 19.3, Tailwind CSS 4.3                                                                                                          | Current stable releases. Next.js moved to 16.4 on 2026-10-26 for its security fixes (security review, S8)                                                                                                                            |
| UI components        | shadcn/ui, `base-nova` style (Base UI primitives)                                                                                                   | shadcn CLI default. Switch before adding many components if Radix is preferred.                                                                                                                                                      |
| Web tests            | Vitest 5 + Testing Library + jsdom; Playwright for the browser end-to-end tests                                                                     | Planned baseline.                                                                                                                                                                                                                    |
| Accessibility checks | axe-core 4.14, a web dev dependency, run inside the Vitest tests                                                                                    | NFR-012. It was already in the tree through `eslint-plugin-jsx-a11y`; jsdom cannot measure contrast or size, so `palette.test.ts` and checks on a phone cover those ([accessibility review](../../testing/accessibility-review.md)). |
| Linting              | ESLint 9                                                                                                                                            | ESLint 9 is end-of-life, but `eslint-config-next` 16.3 depends on plugins (`import`, `jsx-a11y`, `react`) whose peer ranges stop at ESLint 9. Move to 10 when they support it.                                                       |
| Formatting           | Prettier 3 at the root (`singleQuote`, `trailingComma: all`); `eslint-config-prettier`                                                              | Formatting is Prettier's job; ESLint does not duplicate it.                                                                                                                                                                          |
| Database             | PostgreSQL 18 via `pgvector/pgvector:0.8.6-pg18`                                                                                                    | pgvector is available for future RAG; the extension is not enabled until a migration needs it ([ADR-0005](0005-postgresql-and-pgvector.md)).                                                                                         |
| Load testing         | k6, run as an installed program or the `grafana/k6` Docker image, not a package                                                                     | NFR-002. The industry's common choice, with p95 thresholds in the script itself; it stays out of the dependency tree ([performance review](../../testing/performance-review.md)).                                                    |
| CI                   | GitHub Actions: format, lint, typecheck, test, build; the .NET build and tests; the contract and browser tests against PostgreSQL and SeaweedFS     | Same checks as local development. Each job has a time limit (2026-11-06).                                                                                                                                                            |

### The API

| Area             | Choice                                                                                                                                                                                                         | Reason                                                                                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SDK              | .NET 10 SDK 10.0.403 in `global.json`, rolling forward to later feature bands only                                                                                                                             | .NET 10 is the current LTS. The pin makes a developer's machine, CI and the image build with the same compiler.                                                                                                            |
| Images           | `mcr.microsoft.com/dotnet/sdk:10.0.403` to build and `mcr.microsoft.com/dotnet/aspnet:10.0.14` to run, by exact version tag (`apps/api-dotnet/Dockerfile`)                                                     | The same SDK as `global.json`, and a runtime version moved only on purpose.                                                                                                                                                |
| Package versions | Every version in `Directory.Packages.props`, pinned exactly; NuGet lock files (`packages.lock.json`), which CI restores in locked mode                                                                         | One place to read and upgrade, and a restore that cannot pick a different version from the one reviewed.                                                                                                                   |
| Build rules      | `Directory.Build.props`: nullable references, warnings as errors, analyzers at `latest-recommended`; NuGet's audit fails the build on a high or critical advisory                                              | Mistakes the compiler can see stop the build rather than reaching review. Low and moderate advisories stay warnings, so one of little weight does not stop every pull request.                                             |
| Formatting       | `dotnet format`, checked in CI with `--verify-no-changes`                                                                                                                                                      | The C# equivalent of Prettier.                                                                                                                                                                                             |
| Web framework    | ASP.NET Core 10 Minimal APIs, in the module structure of ADR-0006 section 1                                                                                                                                    | Thin endpoints over handlers, without a controller layer or a mediator library.                                                                                                                                            |
| Data access      | EF Core 10 with Npgsql 10; `dotnet-ef` 10.0.14 as a tool of the repository (`dotnet-tools.json`)                                                                                                               | The ORM of the platform, with PostgreSQL enums, `jsonb` and arrays mapped. The tool's version matches the runtime's.                                                                                                       |
| Authentication   | ASP.NET Core Identity; Google and Facebook through Microsoft's handlers, LINE through `AspNet.Security.OAuth.Line` (aspnet-contrib); Data Protection keys in PostgreSQL                                        | [ADR-0003](0003-aspnet-core-identity.md).                                                                                                                                                                                  |
| Password hashes  | `BouncyCastle.Cryptography` for scrypt                                                                                                                                                                         | Verifies the hashes Better Auth wrote before the cutover, which Identity then rewrites in its own format ([ADR-0003](0003-aspnet-core-identity.md)).                                                                       |
| Photo storage    | `AWSSDK.S3`, with checksums only when an operation requires one and, over HTTPS, unsigned payloads; SeaweedFS in docker-compose locally                                                                        | Cloudflare R2 (A3) accepts neither the SDK's default checksums nor its streamed SigV4 uploads; production found the second on 2026-11-06 ([production deployment, section 19](../../deployment/production.md#19-cutover)). |
| Image processing | `NetVips` with its native libvips builds for linux-x64 and win-x64 (LGPL-3.0-or-later, as sharp's are)                                                                                                         | libvips is the library the NestJS API used through sharp, so orientation, metadata removal and resizing stayed the same (FR-017).                                                                                          |
| AI SDK           | `Google.GenAI`, behind the AI module's adapter alone                                                                                                                                                           | [ADR-0004](0004-ai-provider.md).                                                                                                                                                                                           |
| Settings         | `ApiSettings` reads and checks every setting at startup, naming the setting and never its value; in Production it refuses every development default, the repository's throwaway `DATA_PROTECTION_KEY` included | Fail fast on misconfiguration without echoing secret values.                                                                                                                                                               |
| Local secrets    | `dotnet user-secrets` for the API, read in Development only, and by `LanguZe.Tools`                                                                                                                            | The platform's way to keep a developer's provider credentials and Gemini key out of the repository ([local development](../../deployment/local-development.md)).                                                           |
| Tests            | xUnit v3 on Microsoft.Testing.Platform (`global.json`); ArchUnitNET for the architecture rules; `Microsoft.AspNetCore.Mvc.Testing` for the API in process                                                      | One runner for unit, integration and contract tests, and boundary rules that fail the build (ADR-0006, sections 1 and 3).                                                                                                  |

**Why Node 24.20.0 at least (2026-10-08).** On Windows 11 builds 26200 and later, Node 24.15.0 killed test workers at random with exit code `3221226505` (`0xC0000409`), with no output and a different test file each time ([nodejs/node#62260](https://github.com/nodejs/node/issues/62260)). Each of four full e2e runs on 24.15.0 lost at least one file that way. On 24.20.0 and 24.21.0, three full runs each passed with no crash. CI on Linux, like production, never showed it. The floor also takes in the security releases 24.17.0 and 24.18.1.

Deliberately **not** installed yet: Socket.IO or SignalR, Redis, RabbitMQ, Cloudinary. Each is added with the feature that needs it.

## Consequences

- Upgrading TypeScript past 6.0, moving the web app to ESLint 10, moving to pnpm 12, or moving the API to a new .NET major each needs a compatibility check and an update to this ADR.
- A .NET package upgrade is one line in `Directory.Packages.props` and a refreshed lock file; CI's locked restore fails until both are committed.
- A new analyzer warning fails the build. Silence one only with a reason written beside it.
- `dotnet-ef` and the EF Core packages move together, or `dotnet ef` refuses to run against the runtime.
